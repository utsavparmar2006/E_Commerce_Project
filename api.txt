Here is the clear explanation of how the tokens are stored and used in Postman vs. the Frontend, followed by a concrete, step-by-step example of how to perform the Profile Update.

🔑 Where are the tokens stored?
1. The Refresh Token
Where it goes: Saved automatically inside Postman's Cookie Jar (you can see it in the "Cookies" link right below the Send button in Postman).
Why? The backend server returns this token using a Set-Cookie header. Postman behaves like a browser and saves it automatically. It will automatically send this cookie whenever you call the /api/auth/refresh or /api/auth/logout endpoints.
2. The Access Token
Where it goes: It is returned in the JSON Response Body (e.g. { "accessToken": "eyJhb..." }).
Where is it stored?
In Postman: It is not automatically stored. You must copy the value of "accessToken" from the login response body. Then, in your protected requests (like GET Profile or PUT Profile), go to the Authorization tab, select Bearer Token, and paste it there.
In the React Frontend (When we build it): The React app will receive the access token from the API response and keep it in memory (React State/RAM). It is never stored in localStorage or cookies to protect against XSS (Cross-Site Scripting) attacks. When the user closes or refreshes the page, the in-memory token is lost, and React will automatically request a new one from /api/auth/refresh using the secure HTTP-only refresh cookie.
